# Run recovery and checkpoints

Run transitions and their corresponding events are committed atomically. Each run stores an initial cursor and an append-only checkpoint after every completed stage. Checkpoints bind the completed and next stage, immutable run-configuration SHA, canonical workspace identity, registered artifact paths and content, canonical Spec-Kit artifact paths and content, Git HEAD and index tree, managed-path hashes, and bounded loop counters. Event cursors remain monotonic within each run.

Pause requests take effect at the next stage boundary; an in-flight stage is allowed to finish before the run enters `PAUSED`. A kernel-managed lock keyed by the canonical workspace supplements the SQLite lock row, so separate databases cannot write the same workspace. Provider child processes inherit the lock descriptor; the kernel keeps the lease while the provider is alive even if the SpecTide process exits. A stale heartbeat alone never permits recovery while that lock is held. Resume verifies canonical workspace identity, exclusive lock ownership, immutable configuration, checkpoint identity and cursor, registered/canonical artifact hashes, Git HEAD/index, and managed-path hashes before signaling a live owner or claiming an expired one. Restart continuation restores the saved stage cursor, gate verdicts, and loop counters under a new owner lease.

If any check fails, the run becomes `BLOCKED`, appends a `run.interrupted` event containing `WORKSPACE_DRIFT`, releases the abandoned lock/owner, and preserves the run report, checkpoints, artifacts, and workspace files. No automatic reset, checkout, cleanup, or overwrite is attempted. Review the preserved evidence and make any desired repairs explicitly, then start a new run. After process restart, resume a paused run before starting another run; start-time abandoned-run reconciliation blocks expired owners so a different run cannot silently take their workspace.

If a process dies while a stage is in flight, restart uses only the last completed-stage checkpoint. Partial writes to tracked, non-ignored managed, registered, or canonical Spec-Kit artifacts cause fingerprint mismatch and block recovery rather than replaying over them. Resume is available only for `PAUSED` runs with a matching checkpoint and exclusive workspace lock.

The storage layer exposes private database backup and restore operations; dedicated CLI backup/restore commands are not yet available. These operations reject overwrite, check database integrity and schema compatibility, and use private file permissions. Retention expires detailed event/checkpoint payloads after 90 days and caps detailed history at 1,000 runs by pruning the oldest terminal details first. Active runs are not pruned.
