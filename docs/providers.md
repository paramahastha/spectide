# Provider readiness

SpecTide includes a deterministic fake provider and fixture-backed contracts for Claude Code, Codex, and OpenCode adapters. Version-only profile probes persist a non-secret capability snapshot containing the canonical executable path/hash and configured provider directory; editing a profile or detecting reference drift invalidates that snapshot. Route preview and run launch require a matching executable/config identity, an explicit authenticated state, and the requested model, effort, read-only, and write capabilities. Current probes leave authentication as `NOT_PROBED` and do not verify read-only/write behavior, so those live routes are denied before run creation. The workflow has a fixture-validated path for verified Spec-Kit commands and persisted bounded analyze, test-repair, convergence, and final-review outcomes. Real provider authentication and official convergence remain `NOT_RUN`; a mixed live run still blocks while its simulated-E2E gate is incomplete.

Check local tool discovery with `spectide doctor`. Inspect or add a profile with `spectide profiles` and `spectide profiles add NAME --provider PROVIDER --executable EXECUTABLE --scope PATH`. Probe an executable with `spectide profiles probe NAME` or `spectide models probe NAME`. These probes run the executable's version command through SpecTide's bounded runner. They do not inspect credential stores, establish authentication, or discover model catalogs; output keeps those states as `NOT_PROBED`.

The adapters build explicit argument vectors and discard provider event bodies when normalizing streams. Fixture-backed workflow evidence does not claim authenticated provider acceptance. Before live runs can be enabled for a real profile, the project must verify provider authentication and capabilities (including read-only analysis and workspace-write implementation), validate supported model/effort settings, and exercise the adapter against authorized fixtures and live smoke checks. See the [acceptance ledger](acceptance-ledger.md) for current status.
